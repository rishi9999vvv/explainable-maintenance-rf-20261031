# AUCML: Explainable machine failure screening

Approved title: **Explainable AI-Based Predictive Maintenance for Early Detection of Industrial Machine Failure**

This submission includes runnable training code, the original UCI AI4I 2020 CSV, recorded test predictions, a saved model, SHAP explanations, a local browser demo, an editable presentation, a report and individual viva preparation.

**Scope:** AI4I is a synthetic industrial benchmark. Its target indicates failure at the same reading. This experiment evaluates current-reading classification. It does not demonstrate a future warning horizon or performance on actual factory measurements.

## Run the existing demo on this computer

Double-click `run_demo.cmd`, then open **http://127.0.0.1:5000**. Keep its terminal open. Press Ctrl+C to stop it. The app listens only on this computer. No internet is required after dependencies are available.

Choose a saved example, then select **Analyse reading**. The app uses the evaluated saved model and fixed validation-selected threshold. It displays all signed SHAP effects and checks that the explanation reconstructs the model score. The `false_negative` example demonstrates a real limitation from the held-out test set.

The `.packages` directory holds the additional SHAP packages required on the current computer. The local `.venv` can access this computer's existing scientific Python packages. For another computer, use the clean setup below instead of copying that virtual environment.

## Clean setup on another computer

Use Python 3.12 (the exact tested version appears in `results/metrics.json`). From this project directory:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
.\.venv\Scripts\python.exe -m unittest -v test_project.py
.\.venv\Scripts\python.exe app.py
```

The saved model should be loaded only from this trusted submission. Python model files can execute code while loading. Keep the pinned scikit-learn version to avoid model compatibility problems.

## Reproduce the experiment

The CSV is bundled. To fetch a fresh copy from UCI, run `python download_data.py` while online and compare its checksum with `results/metrics.json`.

```powershell
.\.venv\Scripts\python.exe train.py
.\.venv\Scripts\python.exe -m unittest -v test_project.py
.\.venv\Scripts\python.exe build_materials.py
```

Training overwrites generated results and the saved model. It uses seed 42, a 60/20/20 stratified split, five-fold training AP for forest settings and validation F2 for each non-dummy threshold. The primary engineered forest is fixed in the protocol. Test results do not select settings. The saved model stays fitted on the training partition so the threshold and demo match the evaluated model.

The ordered sensitivity analysis uses a separately specified depth-8, leaf-3 forest. It changes both split and model configuration, so it is not a controlled split-only ablation. The report explicitly describes this limit.

`build_materials.py` regenerates the report and numeric slide content. The slide authoring source is kept in `build_slides.mjs`; running it requires the documented presentation authoring runtime. The finished PowerPoint remains directly editable without that runtime.

`requirements-lock.txt` records the tested scientific, SHAP and Flask dependencies, including their supporting packages. `requirements.txt` lists the main experiment packages and is regenerated by training.
